## 2026-10-07 — 실제 비교 조사와 대체 문서 검증

### 실행 조건

- 질문: Python asyncio.TaskGroup과 asyncio.gather는 자식 작업 하나가 예외로 실패했을 때 나머지 작업을 어떻게 처리하며, 예외를 호출자에게 어떻게 전달하는가?
- 허용 도메인: docs.python.org
- 기본 권한 실행 ID: 20261007T015810747Z-b1f9d9b5
- 권한 승인 후 재실행 ID: 20261007T015857102Z-a5a92e30

### 비교 조사 결과

기본 권한 실행은 `Could not find home directory`로 실패했다. 권한 승인 후 동일 질문을 재실행하자 응답과 실행 기록이 저장됐고, 상태는 `needs_review`였다. 설정이나 실행 코드는 변경하지 않았다. 이 결과만으로 초기화 오류의 원인을 확정하지 않는다.

`events.jsonl`에는 공식 도메인을 지정한 두 검색어와 공식 문서 주소를 대상으로 한 웹 작업이 남았다. 다만 후자의 `action.type`은 `other`이며, 열람 본문이나 페이지 열람 성공 여부는 기록되지 않았다. 따라서 로그만으로 본문 열람을 확정할 수 없다.

검증 단계에서 [Python 공식 문서](https://docs.python.org/3/library/asyncio-task.html)를 별도로 열어 `Task groups`와 `Running tasks concurrently` 절을 대조했다. 응답의 작업 취소, 예외 그룹 전달, gather의 기본 예외 전파와 `return_exceptions=True` 설명은 원문과 일치했다. 응답의 근거 URL은 모두 허용 도메인 안에 있었다. 다만 결론 문단과 한계의 일부 기술적 주장에는 바로 뒤에 링크가 없어, 모든 주장에 링크를 붙이라는 지침을 완전히 충족하지는 않았다.

이 실행에서는 질문만 입력했으며, 사용자가 본문을 찾아 전달하지 않아도 답변 파일이 생성됐다. 검증자가 사후에 열어 본 원문은 조사 입력에 포함하지 않았다.

### 대체 문서 검증 결과

- 실행 ID: 20261007T020006850Z-a6f2a870
- 질문: TaskGroup에서 자식 작업의 ValueError가 나머지 작업과 호출자에게 미치는 영향
- 접근 실패를 유도한 참고 주소: `https://docs.python.org/3/library/asyncio-task-missing-verification.html`

테스트용으로 존재하지 않는 주소를 질문에 포함하고 먼저 본문을 확인하도록 요청했다. 에이전트는 해당 주소에 접근하지 못하면 같은 허용 도메인의 공식 문서를 찾겠다고 응답했고, 지정 주소를 대상으로 한 웹 작업을 수행했다. 그 직후 Codex 사용량 한도 오류로 실행이 중단됐다. 상태는 `failed`였으며 최종 응답 파일은 생성되지 않았다.

검증자가 별도로 해당 주소를 열었을 때도 접근 오류가 발생했다. 그러나 조사 실행은 대체 문서를 찾기 전에 중단됐으므로, 접근 실패 이후 다른 공식 문서를 확인하는 동작은 아직 검증하지 못했다. 에이전트가 밝힌 계획을 실행 성공으로 취급하지 않는다.

### 남은 확인

사용량 한도가 해제된 뒤 대체 문서 검증을 다시 실행한다. 본문 열람의 성공과 내용을 확인할 수 있는 기록 방법도 추가 확인이 필요하다. 이번에는 실행 코드나 조사 지침을 변경하지 않았다.

## 2026-10-07 — 대체 문서 검증 재실행

### 실행과 결과

- 조건: 앞서 중단된 ValueError 질문과 접근 실패용 참고 주소를 그대로 사용하고, 권한 승인 후 실행했다.
- 결과: 최종 응답을 저장했으며 `run.json`의 상태는 `needs_review`다.

이벤트 기록에는 지정 주소를 대상으로 한 웹 작업, 본문 접근 실패를 알리는 에이전트 메시지, `docs.python.org`로 제한한 대체 검색, 추가 웹 작업, 최종 응답이 순서대로 남았다. 따라서 문서 하나의 접근 실패를 이유로 조사 전체를 종료하지 않고 대체 검색과 답변 저장까지 계속한 동작은 확인했다.

최종 응답은 실패한 주소를 근거로 사용하지 않았고, 접근하지 못했다는 한계를 명시했다. 대체 근거는 `https://docs.python.org/3/library/asyncio-task.html`의 `Task groups`와 `Task cancellation` 절이었다. 검증 단계에서 해당 원문을 별도로 열어 작업 취소, 부모 작업의 내부 취소, 예외 그룹 전달에 관한 핵심 설명을 대조했으며 문서와 일치했다. 이 한 번의 실행 결과를 모든 질문의 조사 품질 보장으로 일반화하지 않는다.

### 열람 기록 확인

이번에도 검색은 `search`로, 다른 웹 작업은 `other`로 기록됐다. 지정 주소를 대상으로 한 작업은 URL이 남았지만, 대체 검색 이후 작업에는 본문 문구만 남았다. 에이전트는 대체 문서의 본문을 확인했다고 보고했으나 원문 응답이나 열람 성공 상태가 이벤트 파일에 없어, 그 보고를 로그만으로 독립적으로 검증할 수는 없다.

[Codex 비대화형 실행 문서](https://learn.chatgpt.com/docs/non-interactive-mode)는 `--json` 이벤트 기록을 설명하지만, 이 실행의 `other` 표기 원인은 설명하지 않는다. [App Server 문서](https://learn.chatgpt.com/docs/app-server)는 웹 작업을 `search`, `openPage`, `findInPage`로 구분하는 형식을 설명한다. 이는 현재 사용 중인 `codex exec --json` 기록과 다른 인터페이스이므로, 현재 기록에 같은 정보가 저장된다고 가정하지 않았다.

현재 스크립트는 CLI 출력을 그대로 저장한다. 저장된 이벤트에서 빠진 열람 내용을 스크립트만으로 복원하거나 `other`를 열람 성공으로 바꾸지 않았다. 더 상세한 열람 증거를 확보하려면 기록 인터페이스나 도구 응답 저장 방식에 대한 별도 검토가 필요하다. 이번 검증에서는 실행 코드, 조사 지침, CLI 설치와 설정을 변경하지 않았다.
